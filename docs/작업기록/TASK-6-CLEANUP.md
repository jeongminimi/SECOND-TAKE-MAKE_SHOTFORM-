## 새 README에 넣을 것

### 1. 이게 무슨 프로그램인가 (맨 위, 3~4줄)

원곡이 아닌 **LIVE · ACOUSTIC · COVER 무대**에서 그 가수의 새로운 모습을 찾아 인스타그램 릴스로 만드는 도구. 해외 K팝 팬을 보는 계정이라 캡션은 영어가 기본.

### 2. 쓰는 순서 (화면 4단계 그대로)

```
1 영상 고르기   유튜브 주소 붙여넣기 → 채널·제목·썸네일 자동 → 확인 →
                폴더에서 영상 고르기 (또는 파일 올리기)
2 구간과 문구   1:23 형식으로 구간 · 그 시각을 어떻게 알았는지 · 왜 봐야 하는지
3 영상 확인     미리보기 · 모양 4종 · 확대 / 좌우 / 위아래
4 내보내기      output/내보내기/<날짜>_<제목>/
```

「오늘의 추천 받기」로 자동 선곡도 가능하다는 것, 그 결과에 썸네일과 영상 링크가 붙는다는 것도 한 줄씩.

### 3. 선곡 기준 (v2.0)

| 항목 | 배점 |
|---|---|
| 원곡과 얼마나 다른가 | 50 (커버 50 / 편곡 35 / 단순 라이브 0) |
| 영문 공식 표기가 있는가 | 30 |
| 최근 7일 안에 같은 공연자를 안 썼는가 | 20 |

**시점(최근에 올라온 영상인가) 항목은 없습니다.** 오래된 영상이라도 숨은 명곡이면 올릴 수 있어야 하기 때문입니다. 이 기준을 왜 이렇게 바꿨는지 한두 줄 적으세요 — 과거 기록에 v1.0 점수가 남아 있는 이유도 됩니다.

### 4. 영상 모양 4종

| 이름 | 영상 | 원본 가로에서 남는 비율 |
|---|---|---|
| 원본 비율 | 1080×608 | 100% |
| 크게 (기본) | 1080×1200 | 50.6% |
| 꽉 채우기 | 1080×1920, 글씨가 영상 위 | 31.6% |
| 꽉 채우기 · 글씨 최소 | 1080×1920 | 31.6% |

꽉 채울수록 좌우가 잘리니 **좌우 슬라이더로 맞춰야 한다**는 것, 두 명 이상 선 무대는 특히 그렇다는 것을 적으세요. 실제로 겪은 일입니다.

### 5. 설치와 실행

- Node.js 22 이상 (`node:sqlite` 내장 사용 — 별도 DB 설치 없음)
- FFmpeg 필요 (현재 9.1로 동작 확인)
- `npm install` 없이도 돌아감 (`src/web/mini-express.js` 대체 구현). Express가 있으면 그걸 씁니다
- `start-studio.bat` 또는 `node src/web/start.js` → `http://localhost:3000`
- DB가 잠겼을 때는 `fix-db.bat`

### 6. 영상 파일을 어디에 두는가

`storage/` 는 저장소에 올라가지 않습니다(`.gitignore`). 받아서 바로 못 돌립니다.

**`storage/video/` 에 본인 영상 파일을 두면** 1단계에서 「폴더에서 영상 고르기」로 잡힙니다. 이 한 줄이 없으면 아무도 실행하지 못합니다.

### 7. 지금 안 되는 것

사실만 적으세요. 변명도 설명도 붙이지 마세요.

- **인스타그램 자동 업로드 안 됨.** `mode=live` 로 돌리면 예외가 납니다. 영상과 캡션을 내보낸 뒤 직접 올리는 방식입니다
- 유튜브에서 영상을 내려받는 기능 없음. 영상 파일은 직접 `storage/video/` 에 둡니다
- 유튜브 「가장 많이 본 구간」 자동 수집 안 됨. 구간은 운영자가 입력하거나, 소리 크기 기반 추천을 받아 확인합니다
- 게시 성과(조회·저장) 비교 화면 없음
