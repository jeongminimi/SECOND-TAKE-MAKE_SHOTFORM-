# 5순위 — 화면 재배치, URL 자동 채우기, 확대 조절

작성 2026-11-24 · 1~4순위 완료 후 이어지는 작업입니다.

---

## 0. 왜 하는가

지금 화면은 **프로그램이 일하는 순서**대로 짜여 있습니다. 날짜 고르기 → 파이프라인 실행 → 프로그램이 알아서 선곡 → 결과 확인.

운영자가 실제로 하는 행동은 다릅니다. **영상 고르기 → 구간·문구 정하기 → 모양 맞추기 → 내보내기.**

이 간극을 메우는 작업입니다. 그리고 지금 당장 안 해도 되는 것은 전부 왼쪽으로 빼서, 가운데에는 **지금 눌러야 할 것만** 남깁니다.

**순서대로 하세요. 각 단계가 끝날 때마다 보고하세요.** 앞 단계가 뒤 단계의 재료입니다.

# 5-1. 확대·자르기 조절과 즉시 미리보기

4순위에서 좌우 슬라이더를 만들었지만, 지금은 **움직이고 → 전체 렌더(수십 초) → 보고 → 다시 움직이고**를 반복해야 합니다. 실제로는 못 씁니다.

## 5-1-1. 왜 꼭 필요한가 (근거)

16:9 영상을 9:16에 꽉 채우면 가로가 이만큼 버려집니다.

| 모양 | 박스 | 원본 가로에서 남는 비율 |
|---|---|---|
| `clip-standard` | 1080×608 | 100% |
| `clip-large` | 1080×1200 | **50.6%** |
| `clip-full` | 1080×1920 | **31.6%** |

실제로 `clip-full`·`cropX 0.5`로 도겸×승관 영상을 렌더하니 **승관이 화면 밖으로 잘려 나갔습니다.** 운영자가 렌더 전에 보고 맞출 수 있어야 합니다.

## 5-1-2. `zoom`(확대 배율) 추가

템플릿 `video` 키에 두 개를 더합니다.

```json
"video": { "y": 360, "height": 1200, "fit": "cover", "cropX": 0.5, "cropY": 0.5, "zoom": 1.0 }
```

| 키 | 뜻 | 범위 | 기본 |
|---|---|---|---|
| `zoom` | 확대 배율. 1.0 = 박스에 딱 맞춤, 클수록 확대되고 더 잘림 | 1.0 ~ 2.5 | 1.0 |
| `cropY` | `zoom > 1.0`일 때 위아래 어디를 남길지 | 0.0 ~ 1.0 | 0.5 |

**FFmpeg 필터 — 아래는 실제로 돌려서 검증한 문자열입니다. 그대로 쓰세요.**

```
scale={boxW*zoom}:{boxH*zoom}:force_original_aspect_ratio=increase,setsar=1,
crop={boxW}:{boxH}:x=(in_w-out_w)*{cropX}:y=(in_h-out_h)*{cropY}
```

`boxW*zoom`·`boxH*zoom`은 **정수로 내림**하고, **짝수로 맞추세요** (홀수면 H.264 인코딩이 실패합니다). `zoom 1.0 / 1.4 / 2.0` 세 값에서 정상 동작을 확인했습니다.

`zoom = 1.0`일 때는 지금 4순위 필터와 **결과가 완전히 같아야 합니다.** 테스트로 고정하세요.

## 5-1-3. DB

`reels.zoom REAL`, `reels.crop_y REAL` 을 `COLUMN_MIGRATIONS`에 추가합니다.

**`DEFAULT` 값을 주지 마세요. NULL 허용입니다.** 4순위에서 `crop_x`에 적용한 것과 같은 이유입니다 — NULL이 "운영자가 아직 안 골랐다"는 뜻이어야 템플릿 자체 값이 살아납니다. 해석 순서는 `reel.zoom ?? 템플릿.zoom ?? 1.0`.

## 5-1-4. 즉시 미리보기 API

```
GET /api/reel/:id/crop-preview?template=clip-large&cropX=0.3&cropY=0.5&zoom=1.4
→ image/jpeg (1080x1920 한 장)
```

- 전체 렌더와 **똑같은 필터 체인**(scrim·글씨 포함)으로 **1프레임만** 뽑습니다. 측정해보니 **0.22초**입니다.
- `-frames:v 1 -q:v 4`, 음성 없음.
- DB에 **쓰지 않습니다.** 미리보기는 임시 파일이고 끝나면 지웁니다.
- 같은 요청이 연달아 오면(슬라이더를 빠르게 움직임) **마지막 것만 처리**하세요. 화면 쪽에서 150ms 정도 묶어 보내면 됩니다.

## 5-1-5. 화면

영상 아래 「영상 모양」 영역을 이렇게 바꿉니다.

```
[ 원본 비율 ] [ 크게 ] [ 꽉 채우기 ] [ 글씨 최소 ]      ← 모양 4개

확대   1.0 ─────●───────── 2.5
좌우   왼쪽 ──────●────── 오른쪽
위아래 위   ──────●────── 아래          ← 확대 1.0 초과일 때만 보임

┌──────────────┐
│  미리보기     │   ← 슬라이더 움직이면 즉시 갱신 (0.2초)
│  (정지 이미지) │
└──────────────┘

[ 이 모양으로 영상 만들기 ]   ← 이것만 전체 렌더
```

- **슬라이더는 미리보기만 갱신합니다. 절대 자동 렌더하지 마세요.**
- 원본 비율(`clip-standard`)은 안 잘리므로 좌우·위아래 슬라이더를 숨깁니다.
- 확대가 1.0이면 위아래 슬라이더를 숨깁니다.
- 「영상 만들기」를 누를 때만 `POST /api/reel/:id/template`에 `{ template_id, cropX, cropY, zoom }`을 보내 전체 렌더.

## 5-1-6. 클립 기본 모양을 `clip-large`로

자동 실행 시 클립형 릴스의 기본 템플릿을 `clip-standard` → **`clip-large`** 로 바꿉니다.

`clip-standard`는 화면의 3분의 1만 채워서 릴스로는 약합니다. `clip-large`는 절반 이상을 채우면서 두 명이 선 무대도 담깁니다.

`test/templates-analysis.test.js`의 `licensed_clip: ['clip-standard']` 단언이 깨집니다. **의도된 변경이니 `['clip-large']`로 고치세요.** 이미 렌더된 릴스는 `template_id`가 저장돼 있어 바뀌지 않습니다.

# 5-2. URL 붙여넣기 → 자동 채우기 (백엔드)

**이 단계는 백엔드만 만듭니다. 화면은 5-4에서 한 번에 붙입니다.**

지금은 영상 하나 등록하는 데 5단계를 손으로 채워야 합니다. 유튜브 URL 하나로 대부분을 채울 수 있습니다.

## 5-2-1. 영상 ID 뽑아내기

`src/ingest/youtubeUrl.js` 를 새로 만드세요.

받아야 하는 형태:
```
https://www.youtube.com/watch?v=04GSqsX0S50
https://www.youtube.com/watch?v=04GSqsX0S50&list=RD04GSqsX0S50&start_radio=1
https://youtu.be/04GSqsX0S50
https://www.youtube.com/shorts/XXXXXXXXXXX
https://www.youtube.com/live/XXXXXXXXXXX
```

`&list=`·`&start_radio=`·`&t=` 같은 꼬리는 **전부 버립니다.** 영상 ID는 11자입니다. 형식이 안 맞으면 명확한 오류를 내세요.

## 5-2-2. oEmbed 호출

```
GET https://www.youtube.com/oembed?url={encodeURIComponent(정규화된URL)}&format=json
```

**API 키가 필요 없습니다. 유튜브 공식 공개 엔드포인트라 약관 문제도 없습니다.** 실제로 호출해 확인한 응답입니다.

| 필드 | 주신 영상에서 받은 값 |
|---|---|
| `title` | `[COVER] DK X SEUNGKWAN - Die With A Smile (Original Song : Lady Gaga, Bruno Mars)` |
| `author_name` | `SEVENTEEN` |
| `author_url` | `https://www.youtube.com/@pledis17` |
| `thumbnail_url` | `https://i.ytimg.com/vi/04GSqsX0S50/hqdefault.jpg` |

**못 받는 것: 영상 길이, 게시일, 설명.** `published_at`은 DB 필수값이므로 **운영자가 직접 입력**해야 합니다. 자동으로 오늘 날짜를 넣지 마세요 — 틀린 데이터가 조용히 들어갑니다.

네트워크 실패·404·타임아웃(5초) 일 때는 **막지 말고** "자동으로 못 가져왔습니다. 직접 입력하세요"로 넘어가세요. oEmbed는 편의 기능이지 필수 경로가 아닙니다.

## 5-2-3. 제목에서 뽑아내기 (추천만)

`title` 문자열에서 아래를 **추천**합니다.

| 찾을 것 | 패턴 예 | 넣을 곳 |
|---|---|---|
| 버전 종류 | 앞쪽 `[COVER]` `[LIVE]` `(Acoustic)` `(Band Ver.)` | `performance_type` / `arrangement_tags` |
| 공연자 | `[COVER]` 뒤 `-` 앞 → `DK X SEUNGKWAN` | `performer_en` |
| 곡명 | `-` 뒤, `(` 앞 → `Die With A Smile` | `title_en` |
| 원곡자 | `(Original Song : X)` 안 → `Lady Gaga, Bruno Mars` | `original_artist_en` |

**반드시 지킬 것:**

1. **자동 추출 결과는 전부 "추천"입니다.** 화면에서 운영자가 고치지 않으면 저장되지 않게 하세요. 각 칸 옆에 「자동으로 채움 — 확인하세요」 표시.
2. **출처 확인 규칙을 건드리지 마세요.** `name_evidence`·`version_evidence`는 그대로 요구됩니다. 자동으로 채운 값에 출처를 자동으로 달아주지 마세요. oEmbed 응답은 출처의 근거가 될 수 있지만, **그 판단은 운영자가 합니다.**
3. **채널이 공식인지 프로그램은 모릅니다.** `author_name`이 `SEVENTEEN`이라고 해서 공식 채널이라는 보장이 없습니다. 「이 채널이 공식 채널이 맞습니까?」를 운영자에게 물어야 합니다.
4. 패턴이 안 맞으면 **비워 두세요.** 억지로 추측한 값을 넣지 마세요.

## 5-2-4. API

```
POST /api/entry/from-url
body: { url: "..." }
→ { video_id, normalized_url, title, channel_name, channel_url, thumbnail_url,
    suggested: { performer_en?, title_en?, original_artist_en?, performance_type?, arrangement_tags? },
    note: "자동으로 채운 값입니다. 확인 후 저장하세요." }
```

**이 엔드포인트는 DB에 아무것도 쓰지 않습니다.** 읽어와서 돌려줄 뿐입니다. 저장은 기존 5단계 엔드포인트가 그대로 합니다.

# 5-3. 추천 결과에 영상 링크·썸네일 (백엔드)

## 5-3-1. 지금 문제

`official_url`은 DB에 있고 선곡 과정에서 읽기도 합니다(`src/selection/candidates.js`). 그런데 **API 응답에도, 화면에도 안 실립니다.**

- 썸네일은 **저장하지 말고** `platform_video_id`로 화면에서 주소를 만들어 쓰세요: `https://i.ytimg.com/vi/{id}/hqdefault.jpg`. 이미지 파일을 내려받아 보관하지 마세요.

# 5-4. 화면 재배치

**여기서 5-2·5-3의 화면 부분을 한 번에 붙입니다.** 앞 단계에서 화면을 건드리지 않은 이유입니다.

## 5-4-1. 원칙

> 가운데에는 **지금 눌러야 할 것**만. 나머지는 전부 왼쪽.

## 5-4-2. 가운데 — 운영자가 움직이는 순서대로

```
① 영상 고르기
   ┌─────────────────────────────────────────┐
   │ 유튜브 주소 붙여넣기        [ 가져오기 ] │
   └─────────────────────────────────────────┘
   · 가져오면 아래에 채널·제목·썸네일이 뜨고,
     공연자·곡명·버전이 "추천"으로 채워집니다
   · [ 이 채널이 공식 채널이 맞습니다 ] 확인 필요
   · 영상 파일 지정 (storage/video/ 목록에서 고르기)

   또는  [ 오늘의 추천 받기 ] ← 자동 선곡. 결과에 썸네일·링크가 함께 뜸

② 구간과 문구
   · 구간 1:23 ~ 1:48  (자동 추천 + 직접 입력)
   · 왜 봐야 하는지 (자유 입력)
   · 출처 링크

③ 영상 확인
   ┌──────────┐
   │ 미리보기  │  [원본비율][크게][꽉채우기][글씨최소]
   │          │  확대 ──●──  좌우 ──●──  위아래 ──●──
   └──────────┘  [ 이 모양으로 영상 만들기 ]

④ 내보내기
   [ 내보내기 ]  → output/내보내기/<날짜>_<제목>/
```

## 5-4-3. 왼쪽으로 뺄 것

- 운영 기록 (날짜 목록)
- 후보 비교표와 선곡 점수
- 규칙 버전 표시
- 공식 원본 안내 목록
- 데이터 등록 5단계 (채널·영상·곡·후보·클립 개별 편집)

**지우지 마세요. 접어서 왼쪽에 두세요.** 선곡 점수와 판단 근거는 이 프로그램의 핵심 자산이고, 포트폴리오로 보여 줄 부분입니다. **다만 매번 봐야 하는 건 아닙니다.**

## 5-4-4. 「운영 / 데이터 등록」 탭 처리

지금 상단의 두 탭은 **프로그램 구조를 그대로 드러낸 이름**입니다. 운영자에게는 "내가 지금 뭘 하는 화면인지"가 안 보입니다.

위 ①~④ 흐름이 **하나의 화면**이 되고, 「데이터 등록」은 왼쪽의 **「자료 손보기」** 로 들어갑니다. 평소에는 안 열어도 됩니다.

## 5-4-5. 지킬 것

1. **지금 되는 기능을 하나도 잃지 마세요.** 재배치입니다. 삭제가 아닙니다.
2. 기존 API 라우트를 **이름만 바꾸지 마세요.** 테스트가 물려 있습니다.
3. 한 화면에 **버튼 4개 이상 동시에 강조하지 마세요.** 지금 해야 할 단계만 활성화하고 나머지는 흐리게.
4. **비전공자가 읽을 수 있는 한글**로. `dry_run`·`render_status`·`ruleVersion` 같은 말이 화면에 그대로 나오면 안 됩니다. `src/util/terms.js`에 번역을 추가하세요.
