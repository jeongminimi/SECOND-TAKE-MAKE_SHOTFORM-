# 5-4 보완 — 영상 파일 고르기 기능이 아직 없습니다

`TASK-5-UI-REBUILD.md` 의 5-4와 **함께** 읽으세요. 그 지시서가 빠뜨린 내용입니다.

## 무엇이 빠졌나

5-4-2 ① 에 이렇게 써 있습니다.

> · 영상 파일 지정 (storage/video/ 목록에서 고르기)

**이 기능이 지금 없습니다.** 화면 재배치만으로는 안 됩니다. 새로 만들어야 합니다.

확인한 현재 상태:

- 라우트 24개 중 **`storage/video/` 안의 파일 목록을 주는 것이 없습니다.**
- 영상을 붙이는 유일한 방법은 `POST /api/entry/upload/clip` — **브라우저로 올리는 것**뿐입니다.
- 화면(`manage.js`)의 `file_ref` 칸은 업로드 결과를 받아 채우는 **숨겨진 입력칸**입니다. 고를 수 있는 목록이 아닙니다.

## 왜 이게 문제인가

`storage/video/` 에 **이미 세븐틴 공식 영상 30개(약 4GB)가 들어 있습니다.**

지금 구조에서는 그 영상을 쓰려면 **이미 그 폴더에 있는 122MB 파일을 브라우저로 다시 올려서 같은 폴더에 복사**해야 합니다. 말이 안 됩니다.

(이전에 그 영상으로 릴스를 만들 때는 `file_ref` 값을 API에 직접 넣어서 했습니다. 화면으로는 할 수 없는 방법입니다.)

## 만들 것

### 1. 파일 목록 라우트

```
GET /api/entry/video-files
→ { files: [ { file_ref, name, bytes, duration_sec?, mtime } ] }
```

- `cfg.resolved.storage` 아래 **영상 폴더만** 읽습니다. 다른 경로로 나가지 못하게 하세요.
- 영상 확장자만(`.mp4` `.mov` `.mkv` `.webm`). 나머지는 빼세요.
- `file_ref` 는 **DB에 저장되는 것과 똑같은 형식**이어야 합니다. `src/ingest/manualEntry.js` 의 `toStoredPath(cfg, target)` 가 만드는 형식을 그대로 쓰세요. 직접 문자열을 조립하지 마세요.
- `duration_sec` 는 `ffprobe` 로 얻을 수 있지만 **파일 30개면 느립니다.** 넣지 말거나, 목록을 먼저 주고 길이는 나중에 따로 받으세요. 목록이 뜨는 데 몇 초 걸리면 안 됩니다.
- **DB에 아무것도 쓰지 않습니다.** 읽기 전용입니다.
- `res.json` 만 쓰세요 (대체 구현 `mini-express.js` 에 있는 것입니다).

### 2. 화면

① 영상 고르기 안에서, 유튜브 주소를 가져온 **다음** 단계입니다.

```
영상 파일   [ 폴더에 있는 영상에서 고르기 ▾ ]   또는   [ 파일 올리기 ]
            └ 목록: 파일 이름 · 용량 (최근 수정 순)
```

- **기본은 "폴더에서 고르기"** 입니다. 올리기는 두 번째 선택지로 두세요. 운영자는 보통 영상을 먼저 내려놓고 작업합니다.
- 고르면 그 `file_ref` 가 기존 숨겨진 입력칸에 그대로 들어갑니다. **저장 경로는 바꾸지 마세요** — 기존 `POST /api/entry/clip-asset` 이 그대로 받습니다.
- 올리기 기능을 없애지 마세요. 폴더에 없는 영상은 올려야 합니다.

### 3. 테스트 — `test/video-files.test.js`

1. `GET /api/entry/video-files` → 영상 확장자만, 다른 파일은 안 나옴

3. 폴더 밖 경로를 요청해도 나가지 못하는지

5. 영상 폴더가 비어 있을 때 → 빈 목록, 오류 아님
