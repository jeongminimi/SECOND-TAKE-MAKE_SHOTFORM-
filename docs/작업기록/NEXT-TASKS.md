## 1순위 — 내보내기 버튼과 저장 경로

### 1-1. 지금의 문제
`src/export/exportReel.js` 가 `output/내보내기` 폴더를 **통째로 지우고**(`fs.rmSync`) 다시 만든다. 두 번째 릴스를 내보내면 **첫 번째가 사라진다.** 여러 편을 모아야 하는 지금 상황에서는 치명적이다.

### 1-2. 바꿀 것
- 저장 위치를 **릴스별 하위 폴더**로 바꾼다: `output/내보내기/<운영날짜>_<제목>/`
  - 예: `output/내보내기/2026-11-24_DK X SEUNGKWAN covers Die With A Smile/`
- 그 안의 영상 파일 이름도 **제목으로** 바꾼다: `릴스영상.mp4` → `<제목>.mp4`
  - 나머지 파일(`첫화면.png`, `인스타에_올릴_글.txt`, `읽어보기.txt`)은 이름 그대로 둔다.
- **다른 릴스의 폴더를 지우지 마라.** 같은 릴스를 다시 내보낼 때만 그 릴스의 하위 폴더를 교체한다.
- **Windows에서 쓸 수 없는 글자를 지운다**: `\ / : * ? " < > |` 와 끝의 공백·마침표. 제목이 길면 80자에서 자른다. 제목이 비면 `reel-<id>` 를 쓴다.
- `dir` 인자를 직접 준 경우(CLI `--to`)는 지금처럼 그 경로를 그대로 쓴다.

### 1-3. 화면 버튼
- 운영 화면의 **완성된 세로 영상 바로 아래**에 **`영상 내보내기`** 버튼을 단다.
- 누르면 서버에 내보내기를 요청하고, 끝나면 **저장된 폴더 경로를 화면에 그대로 보여준다** (운영자가 복사해서 탐색기에 붙일 수 있어야 한다).
- 새 라우트: `POST /api/export` — 본문 `{ reelId }` 또는 `{ date }`. 기존 `exportReel()` 을 그대로 호출한다.
- 렌더가 끝나지 않은 릴스는 버튼을 비활성화하고 이유를 한 줄로 보여준다.
- 기존 CLI(`npm run export`)는 그대로 둔다.

## 2순위 — 입력 규칙 완화와 구간 입력

### 2-1. "왜 볼 만한가"는 근거 없이도 저장되게
지금은 `why_watch_en` 을 쓰면 `why_watch_evidence` 가 없을 때 **저장이 막힌다**(`validate.js` 의 `why_watch_evidence_required`). 이 계정은 운영자의 취향을 담는 계정이므로, **감상은 출처를 댈 수 없다.**

- `why_watch_evidence_required` **차단을 없앤다.** 근거 칸은 남기되 선택 사항으로 둔다.
- 화면 안내 문구도 바꾼다: "근거가 없으면 비워 두세요"가 아니라 **"직접 보고 느낀 점을 쓰세요. 출처가 있으면 함께 적어도 됩니다."**

### 2-2. 사실은 계속 출처를 요구한다 (이건 절대 풀지 마라)
감상은 자유지만 **사실은 아니다.** 다음은 지금처럼 **차단을 유지**한다.
- `name_evidence` — 공식 영문 공연자명·곡명의 출처
- `version_evidence` — "커버인지 라이브인지"의 출처
- `segment_evidence` — 캡션에 `▶ 시각`을 넣을 때의 출처

이름과 커버 여부가 틀리면 계정의 신뢰가 무너진다. **"이 무대 미쳤다"는 자유롭게, "원곡은 Lady Gaga"는 출처 확인** — 이 선을 코드로 지켜라.

### 2-3. 공식 출처 링크를 명시적으로 확인한다
운영자가 가장 중요하게 보는 것이 "출처가 들어갔는가"다. 지금도 구조상 `official_url` 없이는 영상이 등록되지 않지만, **그 사실이 화면에 보이지 않는다.**
- 드라이런 점검 목록과 운영 화면에 **`공식 출처 링크 있음 — <주소>`** 항목을 눈에 보이게 추가하라.

### 2-4. 구간을 `1:23` 형식으로 입력받는다
운영자는 유튜브의 **"가장 많이 본 구간"** 그래프를 보고 시각을 읽는다. 지금은 초 단위 숫자만 받는다.
- 5단계 클립 입력에서 **`분:초`(예: `1:23`) 입력을 받는다.** 초 단위 입력도 계속 허용한다.
- 시작을 넣으면 **끝을 자동으로 채운다**: 시작 + 25초 (설정값, 최대 30초). 운영자가 고칠 수 있다.
- **시각의 출처를 적는 칸**을 둔다. 기본 안내 문구: `유튜브 "가장 많이 본 구간" 그래프 기준`.
  이 값은 `segment_evidence` 에 들어가고, 그 결과 캡션에 `▶ 1:23` 을 떳떳하게 넣을 수 있게 된다.
- **구간만 바꿨을 때 재선곡 없이 다시 렌더링되게** 하라. 지금은 `--reselect` 를 써야 해서 선곡 기록이 갱신된다.

### 2-5. 구간 자동 추천 — FFmpeg 음량 기반 (설치 불필요)
`all-in-one` 은 PyTorch·NATTEN이 필요해 Windows에서 설치가 어렵다. **지금은 설치하지 마라.**
대신 **이미 깔려 있는 FFmpeg만으로** 1차 추천을 만든다.

- `ffmpeg -i <파일> -map 0:a -af astats=metadata=1:reset=<N>,ametadata=print:key=lavfi.astats.Overall.RMS_level -f null -` 로 구간별 음량(RMS)을 읽는다. (동작 확인 완료)
- 가장 음량이 높게 지속되는 25초 구간을 추천값으로 삼는다.
- **`src/analysis/structure.js` 가 이미 쓰는 JSON 형식을 그대로 만들어라.** 추천 → 운영자 승인 → 같은 릴스 재렌더링 구조가 이미 있으므로 **분석기만 갈아 끼우면 된다.** 새로 만들지 마라.
  - `downbeats` 는 빈 배열로 둬도 된다. 기존 코드가 빈 경우를 처리한다.
- **이름을 정직하게 붙여라.** 음량이 크다고 후렴이 아니다. 라벨은 `peak`, 화면 표기는 **`소리가 가장 큰 구간 (후렴일 가능성)`**. 절대 `후렴`이라고 단정하지 마라.
- `config` 의 `analysis.labelPriority` 에 이 라벨을 추가하라.

## 3순위 — 선곡 기준 v2.0

계정의 취지가 **"원곡이 아닌 라이브·커버로서 숨겨진 명곡을 찾아주는 것"**으로 확정됐다. 지금 배점은 이와 어긋나는 항목이 있다.

### 3-1. "소개할 시점" 20점을 없앤다
숨은 명곡은 보통 오래된 영상이다. 14일 내 공개를 요구하면 **콘셉트에 가장 맞는 후보가 감점된다.**
- `weights.timeliness` 와 점수 계산에서 **완전히 제거**한다.
- **`occasion_note` · `occasion_date` · `occasion_evidence` 컬럼과 입력칸은 남긴다.** 점수에서만 빼고, 메모와 캡션 재료로는 계속 쓴다. **데이터를 지우지 마라.**

### 3-2. "버전의 차이"를 단계로 나눈다
지금은 커버든 밴드 편곡이든 똑같이 40점이다. 취지에서 보면 무게가 다르다.

| 항목 | 배점 | 판정 |
|---|---|---|
| **버전의 차이** | **50** | **커버 50** (`performance_type = 'cover'`) · **편곡 버전 35** (커버는 아니지만 band·acoustic·orchestra 등 태그가 있음) · **단순 라이브 0** |
| **영어 소개 정보** | **30** | 지금과 동일 (공식 영문명 + 근거) |
| **최근 중복 회피** | **20** | 지금과 동일 (최근 7일 같은 공연자 없음) |

- 커버이면서 편곡 태그도 있으면 **50점**(가장 높은 단계)을 준다.
- `version_evidence` 가 없으면 지금처럼 **후보에서 제외**된다. 이건 그대로다.
- 점수 이유에 **어느 단계로 판정했는지**를 한국어로 적어라. 예: `다른 아티스트의 곡을 커버한 무대입니다 (50/50).`

### 3-3. 규칙 버전을 올린다
- `selection.ruleVersion` 을 **`v2.0`** 으로 바꾼다.
- 기존 선곡 기록의 `rule_version` 은 **고치지 마라.** v1.0으로 남아야 "어떤 기준으로 뽑았는지"가 보존된다.

### 3-4. 테스트는 깨지는 게 정상이다
지금 테스트는 옛 배점을 전제로 한다. 아래는 **고장이 아니라 의도된 변경**이므로 테스트를 새 기준에 맞게 고쳐라.
- `test/pipeline.test.js` 의 `[100, 100, 100, 100]` → 새 배점에서는 커버가 100, 편곡이 85가 된다
- `test/entry.test.js` 의 `score.total === 100`
- 그 외 점수에 의존하는 단언

**새로 추가할 테스트**
- 커버가 편곡 버전보다 높은 점수를 받는다
- 단순 라이브는 버전의 차이 0점을 받는다
- 오래된 영상이라는 이유만으로 감점되지 않는다 (시점 항목이 사라졌는지 확인)
- 합계 최대가 100이다
